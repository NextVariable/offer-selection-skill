# 已知限制

- 证据校验依赖 Agent 记录真实打开的页面和定位信息。程序能核查这份记录与结论的范围、时间和依赖关系。页面是否真正支持主张，要由 Agent 或审查者在原始页面核实。
- 被拦截的网页、尚未发布的入学或招聘周期、个人奖学金证明和临近付款日期，可能让结论只能保持有条件。不同届别或分校的近似项目不能补作确认。
- 费用需要适用届别、币种和有依据的支出区间。已打开的网页只能证明它覆盖的分项。全程可承担和某一付款节点充足是两个判断。
- Python 3.10+ 和宿主执行权限决定可否自动校验。网络研究权限、安装、运行以及跨客户端行为分别验证。详见[兼容性](COMPATIBILITY.md)。
- 旧版台账的 Confirmed 声明可能没有原始网页观察记录。需要复核原网页并补记，或者用离线 audit 生成降级副本。
- 给用户的报告不需要展示内部 JSON。宿主平台的对话保留与本地临时文件保护是不同边界，详见[隐私](PRIVACY.md)。
- 快速报告的费用区间只反映已录入台账；未量化行会被显式列出，但不等于成本研究已经完成。离线校验通过也不等于宿主 Agent 按 Skill 契约执行，两者需分别验证。
- 本地计算使用货币最小单位，部分报告会保留这些数值。费用的零下界若来自未量化支出或资助，只能用于表示区间边界。
- v2 Harness 的程序检查只判断来源记录的形式、范围、适用期、访问时效、依赖和冲突；“来源是否真正支持具体主张”仍需模型复核或人工裁定，验证摘要会明确标注这一点。
- Harness 不会自动补查未完成的研究，也不会替宿主调用模型或浏览器。宿主中断、额度不足或无法联网时，任务会保持未完成或 blocked，并保留核实路径。因工具错误、部分结果或来源未打开而 blocked 的任务会在 `resume` 时重试；证据矛盾会保持 blocked，等待人工裁定。
- 研究覆盖检查只能看到 Case 中已经声明的 Gate、证据和任务。若 Agent 完全没有为某个必要主题创建任何对象，覆盖诊断会按职业路径列出缺失类别，但无法证明该主题真的不需要；它也不阻断推荐，需要宿主研究或记录不适用理由。
- Checkpoint 是可审计标记，不是可回滚快照。`resume` 总是重新核验当前文件，不会静默回到旧检查点；`checkpoint_drift` 会报告检查点之后失去确认的证据或新增的开放任务。
- v2 尚未在原生 Claude Code / Codex CLI 中完成端到端验收；现有证据是单元/集成/安装器测试和回退运行，不能替代原生宿主通过。
- 目标岗位或实际雇主可能有独立的资格与招聘窗口。同一职业路径覆盖多种岗位时，仍需核对决定性的岗位条件。建议不保证录用、工作许可或学术升学。
